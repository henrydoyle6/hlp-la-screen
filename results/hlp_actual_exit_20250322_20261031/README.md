接管范围：2025-03-22 至 2026-10-31（UTC）。依据最新校验 CSV1 的 22,044 笔接管、443 个接管组，全部精确关联，未匹配数为 0。

## 获取一个完整 CSV

完整 CSV 为 265,635,701 字节，超过 GitHub 普通单文件限制，因此本目录保存 6 个带相同表头的 CSV 分片。每个分片均可单独阅读。

使用 Python 3.11 或更新版本执行：

```sh
python restore_csv.py
```

脚本先验证各分片 SHA256，再去掉后续分片的重复表头，恢复一个与本地交付逐字节相同的 UTF-8 BOM、CRLF CSV；不会覆盖已有文件。完整 SHA256：`429513e89114f0a13828a25a91e522b6c7a99c47ae861b1d1aa2552ae3626073`。

## 阅读和计算口径

- 首先筛选 `记录类型=成交`。诊断行不代表成交。
- 用 CSV1 接管事件编号找到接管成交，再用前、后仓位周期编号查看整个周期。接管组编号仍沿用 CSV1，仓位周期不等同于原接管组。
- 正仓位为多头，负仓位为空头。买入增加有符号仓位，卖出减少。动作来源与仓位动作分开记录，反向接管可能减少旧仓位。
- 一笔穿零成交只保留一行，记录平仓量和新开仓量，连接前后周期。`PnL所属周期编号`指向被平仓的周期；原始 PnL 不重复分摊。
- `原始closedPnl` 只保留 HLP 这一侧的官方字符串。空值表示官方未提供，不等于零。不会使用被清算人的 PnL、accountValue 或推算值替代。
- `退出状态`表示观察到的仓位终点，必须结合 `轨迹完整性`、`PnL完整性`和原因代码解读。`与上一笔仓位差额`为原始 startPosition 减上一笔计算后仓位，原样展示差异。
- 同一周期包含多次接管时，不能唯一分摊退出到每次接管。周期内普通交易也保留。JSON 中的 PnL 合计仅用于逐行复核，不是单次接管收益或包含费用、funding 的 HLP 净损益。
- 退出方式计数：{"普通成交": 527, "被清算": 902, "接管": 7, "结算": 1}。这些分类来自原始官方字段，未将被清算、结算或反向接管统一称为普通平仓。

## 覆盖与验证

本地归档截至 2026-10-31，使用 14,136 个来源文件及已修复清单。对于此前完整扫描已证明不含四个目标 HLP 地址的文件，核对签名后复用零命中凭据；其余文件重新流式读取。不是用仅有接管成交的缓存推断退出。

官方免费 userFillsByTime 查询使用 aggregateByTime=false，保留分页回执并验证与本地末条记录重叠。四个地址均确认衔接；本次统一查询截止 1794221505391（UTC Unix 毫秒）。后续不含目标接管的独立周期不纳入结果。已知归档缺口和期初覆盖不足继续保留，不声明发现了缺口内未知接管。

14 项合成测试覆盖多空、重叠接管、反转、不同账户、缺口、缺失 PnL、官方接口空响应及分页不能前进。独立 CSV 回读验证全部成交唯一性、原始数值字符串、逐笔仓位算术及全部 CSV1 接管关联。真实历史验证与合成测试分别记录。

本目录仅包含派生 CSV、还原工具及紧凑核验。原始 fills、接口响应、缓存、SQLite 和凭据均未提交；本次 AWS 请求数为 0。没有修改原 CSV1/CSV2/CSV3 或生产计算引擎。
