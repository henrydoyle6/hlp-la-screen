# CSV1 与 443 个 episode 的含 M 盈亏

计算日期：2026-11-16。使用用户明确指定的 `csv1_20250322_20261031_含account_value_开仓价清算价_U_M.csv`，逐笔关联已经核验的 FIFO 仓位价差盈亏。用户已确认本次保持原来的 **443 个 episode**。

## 公式、符号与范围

`HLP盈亏_含M_USDC = FIFO仓位盈亏_USDC + 原文件中的M`。

输入文件的 `accountValue`、`U`、`M` 均逐格保留。其既定公式是：q 为本笔有符号数量（多仓正、空仓负），U =（原始清算标记价 − 被接管用户平均开仓价）× q，M = accountValue − U。本次不另选价格、不按名义金额重新分摊 M，也不把 M 取绝对值或截断负值。

FIFO 盈亏已经包含多空方向，直接与带符号 M 相加，空头不再整体乘一次负号。结果大于0记盈利、小于0记亏损、等于0记持平，缺M记未确定。资金费和手续费继续不计。

每笔盈亏归原 CSV1 的接管组编号，退出跨越 episode 时仍归原接管批次。222笔纯抵消接管的 FIFO 新批次盈亏为0，其 M 仍按用户指定公式计入该接管所在 episode；触发旧仓退出的 FIFO 盈亏已经归回旧批次，不再额外计入。

## 口径限制：逐笔 M 不是去重后的资金转移

以上数字是**按用户指定的逐笔 M 相加的研究口径**，不能据此直接宣称HLP实际净赚了对应金额。

现有官方清算关联证据中，22,044笔对应18,406个“被清算账户 × 毫秒时间 × 交易哈希”包键，1,521个包键出现在多笔接管中，共涉及5,159笔记录、3,638次超出首笔的重复出现。原文件中的accountValue可能因此在多行重复。逐笔M同样沿用该原字段；本次没有擅自去重或重新分配，也没有证明其合计等于真实转入保证金或净权益。包键计数只是重复范围诊断，不是自动去重规则。

现有FIFO也仍保留官方PnL未完全对账的边界：其原始周期核对状态随逐笔结果一起保留。给定字段的算术验证通过，不等于所有输入具有完整经济转移或官方成本解释。
