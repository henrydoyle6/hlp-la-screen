## 均价计算与边界

本地 node_fills_by_block 保存成交 `px`、`sz`、`startPosition` 和 `closedPnl` 等字段，没有直接的历史持仓 `entryPx`。从零仓位开仓，或从穿零反向成交的剩余新仓位开始，沿同一用户、币种的成交重放：同向加仓按数量加权，减仓保持均价，全平归零。数量采用 Decimal 精确衔接，同毫秒采用原生流顺序或唯一可证明的数量链；不以成交 ID 大小猜测先后。主均价还要求开仓起点至接管时刻具备连续的可用来源时间覆盖，避免遗漏净数量为零的中间往返交易。

重建值是依据观察到的成交链计算的理论成本，未声称读取了原生账本 entry notional 或当时界面的历史 entryPx。近期 WebSocket 快照只补充成交，不单独证明某段历史完整；空接口回执也不证明更早成交不存在。只采用已完整导入的接口回执作为时间覆盖依据，排除已知错时或被替换的旧 ZIP 名义小时覆盖。可用来源的时间覆盖仍不能证明提供方从未遗漏记录。缺起点、数量断链、顺序不唯一、时间覆盖不足和来源冲突均保留空值。使用局部 60 位 Decimal 精度，不改变调用方 Decimal 上下文。

被接管方全平记录均经身份、币种、毫秒时间、哈希、价格、数量和反向平仓方向匹配。零手续费全平时，单独计算 `执行价 - closedPnl / (方向符号 × 平仓数量)`。原始 closedPnl 的精度会与理论成交链成本产生差别，所有差异保留；该隐含值没有覆盖主均价，HLP 收到仓位一侧的 PnL 没有用于反推用户成本。

三笔旧式 node_trades 没有 markPx，官方目标窗口未返回目标成交；官方 txDetails 已精确核对三笔清算交易的哈希、账户和毫秒时间，但交易详情没有 markPx。已有 0xArchive 免费账户请求均返回 `403 history_window_exceeded`。Hypedexer/Enigma 导出在用户授权验证码后返回 `Export failed: Job not found`，没有取得文件，不能视为“没有历史成交”的证据。

三笔的开仓链已分别从本地原始 node_trades 找到，均价不再缺失。索引中的 36、23,366、3 条历史原始记录数分别与完整读入的原档匹配，未丢失行。标记价参考来自各自单仓位官方清算账本的 `liquidatedNtlPos / abs(szi)`；已检查币种和数量匹配。对 17,555 笔有原始标记价的同类记录交叉核验，其中 17,377 笔精确一致，178 笔有名义金额序列化尾差，最大相对差约 1.88e-16。另对较早时期的 45 笔找回的原始标记价核对，44 笔精确一致、1 笔存在约 8.51e-17 的相对尾差。这只支持推算参考，不证明恢复了缺失的原始 markPx；kPEPE 尾差原样保留。清算标记价与接管执行价、理论触发清算价是不同概念。

## 来源、复核和使用

已复用本地目标小时完整成交、主要 2025-10-10 接管群缺口账户此前一个月的完整小时和旧账户的开仓生命周期，交叉核验全部 16,431 个用户的官方近期成交快照，并按限速补查更早 userFillsByTime。正按已找到的开仓起点和接管时间补读可信本地原档。官方文档说明每次最多 2,000 笔，历史有保留范围；实际回执覆盖与本轮每账户 20 页限制记录在 [核验证据](victim_price_validation.json)，不能把接口保留范围当作账户完整生命周期，也不把达到本轮分页上限的记录归因为“没有历史”。没有请求 AWS、购买接口或升级套餐。

官方规则与字段参考：[开仓均价与 PnL](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/entry-price-and-pnl)、[用户成交接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint)、[清算](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/liquidations)。

CSV 使用 UTF-8 BOM、CRLF；精确 SHA256、数量和接口范围见核验证据。离线逐格复核：

```bash
python tools/validate_csv1_victim_prices.py \
  results/csv1_full_20250322_20261031/csv1_20250322_20261031_victim_prices_zh.csv \
  --source results/csv1_full_20250322_20261031/csv1_20250322_20261031_account_value_zh.csv
python -m unittest test_victim_entry_math test_csv1_victim_prices_result -v
```

[核验笔记](victim_prices_audit.ipynb) 四个代码单元已通过标准 CPython 顺序执行并捕获输出，没有进行 Jupyter 图形界面渲染。CI 复读已交付 CSV 并运行合成测试，不重新访问原始文件或查询历史 API。原始 fills、接口回执、日志、数据库和凭据只保留在本地。此中文研究增补版不改变原生 CSV 头或导入器，不直接作为要求英文原生表头与完整区块号的 CSV1_INPUT；旧运行与旧断点格式保持不变。
