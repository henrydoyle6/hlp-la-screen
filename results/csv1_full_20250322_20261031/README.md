## 规则和覆盖限制

- 使用 `v0.3.1`（`bd67b61287afba08eb0ab691c663690afb83335f`）原四个 HLP 接收账户及原分组/汇总引擎。45 列的顺序和含义保留，只翻译表头；数据单元格与该引擎对同一标准化输入的输出逐格一致。
- node_trades 使用显式 `LiquidatedCross` / `LiquidatedIsolated` 的接收侧识别；node_fills 和 node_fills_by_block 使用 HLP 接收的 backstop 成交，排除被清算侧与 ADL。没有通过仓位净变化猜测接管方向。
- 忽略 2025-05-25 与 2025-07-27 两处格式衔接缺口。它们不触发分段；同币种、同方向按相邻接管间隔 **≤30 分钟** 连续合并，接管组本身可以超过 30 分钟。
- 所有记录按真实成交时间筛选、排序。部分文件的区块时间早于文件名小时，已核对其 `local_time` 与文件名小时对应；没有把文件名小时当作成交时间。
- 本地及已准备的最早原始记录为 **2025-03-22 10:48:33.216 UTC**。正式起点 01:00 至该时刻之前没有原始覆盖；已在原有问题列中写入 `MISSING_FILLS_FILE`，不能把这段当作零接管。未生成未知成交。
- 初始覆盖缺失之外，本轮已扫描输入的 JSON/外层结构检查错误为 0。此前 2025-11-25 两个修复分片也已完整重读通过。
- 仅生成 CSV1；没有还原订单簿、计算 LA 或生成 CSV2/CSV3。仓库计算源码保持原样。离线适配和完整原始数据检查在本地执行。

## 与原生导入器的区别

这份交付按用户要求使用中文表头并保留未知区块号为空。
现有 `CSV1_INPUT` 仍要求英文表头和完整的合法区块号，**不能直接导入这份中文结果**；本次没有改变导入、回放或计算逻辑。
本地保存的英文中间输出也包含同样的空高度，不把它声称为已通过完整原生导入的文件。
